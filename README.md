# ZATO.Entry

Единое окно въезда в закрытый город: превращает неизвестный срок ожидания
в дату на календаре. Пилотный профиль — ЗАТО Саров.

> Сроки и состав шагов в модели — оценочные допущения, а не официальные
> данные органов власти; данные сотрудников в примерах сгенерированы.
> Не является официальным сервисом администрации ЗАТО Саров, АО «Атом-ТОР»
> или Госкорпорации «Росатом».

Это серверная версия продукта, выросшая из
[статического прототипа](https://startoken.ru/en/cases/zato/).

## Что уже работает

| Модуль | Что делает |
| --- | --- |
| Дорожная карта | Граф шагов с зависимостями, расчёт дат в рабочих и календарных днях, критический путь, резервы, вилка «рано — базово — поздно» |
| Три сценария | «Визит», «Работа», «Бизнес» на одном ядре; ответы анкеты перестраивают граф |
| Сроки от эксперта | Любой срок переопределяется в запросе; допущения помечены и считаются |
| Предпроверка пакета | Обязательные поля, форматы, комплект документов, возраст, замена паспорта в 20 и 45 лет, дубли, реалистичная дата въезда |
| Кабинет организации | Штат со сроками пропусков, отметка о продлении, загрузка списком, сохранённые планы |
| Календарь продлений | Срок подачи за 45 дней до окончания пропуска, статусы, пакеты по неделям, подписка `.ics` для Outlook и других календарей |
| Хранилище | PostgreSQL с миграциями; без базы сервис работает в памяти |
| Профиль города | Формы, сроки, точки отказа и оргструктура — в `profiles/sarov.json`, ядро от города не зависит |

## Запуск

С базой данных, через Docker:

```sh
cp .env.example .env      # задайте POSTGRES_PASSWORD
make up                   # http://localhost:8080
```

Без Docker нужен Go 1.24+:

```sh
make run                  # данные в памяти, пропадут при перезапуске
DATABASE_URL='postgres://user:pass@localhost:5432/zato?sslmode=disable' make run
make test
```

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL. Миграции применяются при старте. Без неё — хранилище в памяти |
| `ZATO_ADDR` | Адрес сервера, по умолчанию `:8080` |
| `ZATO_TEST_DATABASE_URL` | База для тестов хранилища; без неё тест PostgreSQL пропускается |

Сценарий открывается по ссылке: `/#visit`, `/#work`, `/#business`;
сохранённый план — `/#plan=<id>`.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/v1/profiles` | Список городов |
| GET | `/api/v1/profiles/{city}` | Профиль: сценарии, анкета, виды пропусков |
| POST | `/api/v1/plans` | Рассчитать дорожную карту; с `"save": true` — сохранить |
| GET | `/api/v1/plans/{id}` | Сохранённый план |
| POST | `/api/v1/passes/validate` | Предпроверка пакета заявки |
| POST | `/api/v1/renewals/calendar` | Календарь продлений без кабинета (`?format=ics`) |
| POST | `/api/v1/orgs` | Создать кабинет; ключ доступа выдаётся один раз |
| GET | `/api/v1/orgs/me` 🔑 | Данные кабинета |
| GET | `/api/v1/orgs/me/plans` 🔑 | Сохранённые планы |
| GET, POST | `/api/v1/orgs/me/staff` 🔑 | Штат; POST добавляет или обновляет по коду |
| DELETE | `/api/v1/orgs/me/staff/{code}` 🔑 | Удалить сотрудника |
| POST | `/api/v1/orgs/me/staff/{code}/renew` 🔑 | Отметить продление |
| GET | `/api/v1/orgs/me/renewals` 🔑 | Календарь продлений штата |
| GET | `/api/v1/feeds/{feed_token}/renewals.ics` | Подписка на календарь, только чтение |
| GET | `/healthz` | Готовность сервиса и базы |

🔑 — нужен заголовок `Authorization: Bearer <ключ доступа>`.

```sh
curl -X POST localhost:8080/api/v1/plans -d '{
  "city": "sarov",
  "scenario": "business",
  "start_date": "2026-11-16",
  "answers": {"founder_nonresident": true, "needs_fitout": false},
  "overrides": {"b_check": 60}
}'
```

## Устройство

```
cmd/zato-entry      точка входа, HTTP-сервер
internal/engine     ядро: граф, календарь, расчёт дат, критический путь
internal/profile    модель профиля города и его проверка при загрузке
internal/planner    анкета → дорожная карта в трёх вариантах сроков
internal/passes     предпроверка пакета и календарь продлений
internal/store      хранилище: PostgreSQL и память за одним интерфейсом
internal/api        REST API, доступ по ключу, ограничение частоты
profiles/           профили городов (JSON, встраиваются в бинарник)
web/static/         веб-интерфейс без сборки и зависимостей
```

Новый город — новый файл в `profiles/`: код менять не нужно. Профиль
проверяется при старте (ссылки шагов, циклы, сроки, оргструктура), сервис
с некорректным профилем не запустится.

## Данные и доступ

- Пакет заявки с паспортными данными проверяется в памяти и никуда не
  сохраняется. В базе о сотруднике лежит только код, необязательное имя
  и срок пропуска.
- Кабинет открывается ключом доступа. Ключ показывается один раз, в базе
  хранится его хеш; восстановить утерянный ключ нельзя.
- Ссылка на календарь содержит отдельный ключ только для чтения.
- Планы без кабинета доступны по ссылке и удаляются через 30 дней.
- В журнал пишутся метод, путь и статус запроса, без тел и ключей.
- Перед публикацией в интернете сервис нужно поставить за HTTPS-прокси.

## Границы

- Не сокращаем срок спецпроверки — делаем дату известной.
- Не обещаем результат рассмотрения заявки.
- Не заменяем МФЦ и бюро пропусков.
- Не гарантируем совпадение регламентов в разных ЗАТО.
