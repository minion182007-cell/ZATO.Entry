# ZATO.Entry

Единое окно въезда в закрытый город: превращает неизвестный срок ожидания
в дату на календаре. Пилотный профиль — ЗАТО Саров.

> Сроки и состав шагов в модели — оценочные допущения, а не официальные
> данные органов власти; данные сотрудников в примерах сгенерированы.
> Не является официальным сервисом администрации ЗАТО Саров, АО «Атом-ТОР»
> или Госкорпорации «Росатом».

Это серверная версия продукта, выросшая из
[статического прототипа](https://startoken.ru/en/cases/zato/).

## Что уже работает

| Модуль | Что делает |
| --- | --- |
| Дорожная карта | Граф шагов с зависимостями, расчёт дат в рабочих и календарных днях, критический путь, резервы, вилка «рано — базово — поздно» |
| Три сценария | «Визит», «Работа», «Бизнес» на одном ядре; ответы анкеты перестраивают граф |
| Сроки от эксперта | Любой срок переопределяется в запросе; допущения помечены и считаются |
| Предпроверка пакета | Обязательные поля, форматы, комплект документов, возраст, замена паспорта в 20 и 45 лет, дубли, реалистичная дата въезда |
| Календарь продлений | Срок подачи за 45 дней до окончания пропуска, статусы, группировка в пакеты по неделям, выгрузка `.ics` |
| Профиль города | Формы, сроки, точки отказа и оргструктура — в `profiles/sarov.json`, ядро от города не зависит |

## Запуск

Нужен Go 1.24+. Внешних зависимостей нет.

```sh
make run          # http://localhost:8080
make test
make docker       # образ zato-entry
```

Адрес задаётся переменной `ZATO_ADDR` (по умолчанию `:8080`).
Сценарий открывается по ссылке: `/#visit`, `/#work`, `/#business`.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/v1/profiles` | Список городов |
| GET | `/api/v1/profiles/{city}` | Профиль: сценарии, анкета, виды пропусков |
| POST | `/api/v1/plans` | Построить дорожную карту |
| GET | `/api/v1/plans/{id}` | Получить сохранённый план |
| POST | `/api/v1/passes/validate` | Предпроверка пакета заявки |
| POST | `/api/v1/renewals/calendar` | Календарь продлений (`?format=ics` — iCalendar) |
| GET | `/healthz` | Проверка готовности |

```sh
curl -X POST localhost:8080/api/v1/plans -d '{
  "city": "sarov",
  "scenario": "business",
  "start_date": "2026-11-16",
  "answers": {"founder_nonresident": true, "needs_fitout": false},
  "overrides": {"b_check": 60}
}'
```

## Устройство

```
cmd/zato-entry      точка входа, HTTP-сервер
internal/engine     ядро: граф, календарь, расчёт дат, критический путь
internal/profile    модель профиля города и его проверка при загрузке
internal/planner    анкета → дорожная карта в трёх вариантах сроков
internal/passes     предпроверка пакета и календарь продлений
internal/store      хранилище планов (сейчас — в памяти)
internal/api        REST API
profiles/           профили городов (JSON, встраиваются в бинарник)
web/static/         веб-интерфейс без сборки и зависимостей
```

Новый город — новый файл в `profiles/`: код менять не нужно. Профиль
проверяется при старте (ссылки шагов, циклы, сроки, оргструктура), сервис
с некорректным профилем не запустится.

## Границы

- Не сокращаем срок спецпроверки — делаем дату известной.
- Не обещаем результат рассмотрения заявки.
- Не заменяем МФЦ и бюро пропусков.
- Не гарантируем совпадение регламентов в разных ЗАТО.

Пакет заявки с персональными данными проверяется в памяти и не
сохраняется; в журнал пишутся только метод, путь и статус запроса.
